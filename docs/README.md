# docs/ · 文档地图与**单一真相源**

> 这份文件**不是内容文档**，只回答两个问题：
> **① 每份文档该写什么；② 同一条边界陈述，以哪一份为准。**
> 内容在各属主文件里，这里只给索引与规矩。

## 2. 单一真相源表（0.11.2 起 · 对应体检 §A5）

一条陈述**只能有一个属主**。非属主文档可以引用结论，但**不许复述细节** ——
复述 = 第二份真相，迟早漂移。这不是假设：0.11.0 体检的 **B1** 就是
"6 份文档一致复述了同一个**并不存在**的对策（`VectorIndex`）"，而唯一的证据只有那 6 份文档。

| 陈述 | 属主（唯一真相源） | 其余文档怎么写 |
|---|---|---|
| 单进程 / 零第三方依赖（**架构承诺**） | `architecture.md` §10 原则 1、2、7 | 只引用，不重述理由 |
| 规模边界（暴力扫描 / 10 万 chunk / 并发 / 定时任务 / 通知 / 指标…） | `architecture.md` **§9** | 只引用 §9 |
| 检索性能数字（P50 / P95 / 召回损失口径） | `benchmark.md` | **不给数字**，只给链接 |
| 并发与长稳数字（吞吐 / 分位 / 事件循环滞后） | `benchmark-concurrency.md` | 同上 |
| 运维边界（进程停机语义、告警会丢、备份与恢复、TLS 前提） | `deploy.md` **§10** | 只引用 §10 |
| 前端 CSP 纪律与内联样式的冻结值 | `architecture.md` **§7.6** | 数字只写一次 |
| 前端分片清单与加载顺序 | **代码**（`public/index.html` 的 `<script>` 顺序） | 文档只说明"以 `index.html` 为准"（架构说明见 §7.8） |
| 路由清单 / 权限矩阵 | **代码**（运行时路由表 + `permissions.mjs`） | 文档不抄清单，只给读取入口（`GET /api/system/routes`） |
| **回归与审计的清单、用例数、通过判据** | **代码**（`tools/gate.mjs` 的检查清单 + 各脚本末行 `DONE fails=N` / `DONE violations=N` / `DONE leaks=N`） | 文档不抄"该跑哪几个脚本"，只给入口 `node tools/gate.mjs`（列清单：`--list`）；要用例数就注明"现读自门禁汇总"，**不要手写**（0.13.1 起这条与"路由 113 条"是同一类漂移） |

| 安全边界处置（自助找回 / 登录退避副作用 / MFA 交付状态） | `security-review-2026-10.md` **§4** | 只引用 §4 |

## 3. 三类文档，三种读法（这一条是 §A5 的解法）

体检 §A5 的担心是"「单进程」出现在 39 处，改一次要改 7 个地方"。
**但"把 39 处都删掉"是错的解法** —— 其中很大一部分写在版本记录与历史报告里，
它们记录的是**当时怎么判断的**，删掉就等于销毁决策证据。正确解法是让三者各归其位：

| 类别 | 是哪些 | 读法与写法 |
|---|---|---|
| **属主**（normative） | `architecture.md` / `deploy.md` / `benchmark*.md` | 陈述**当前事实**。要改边界，**改这里**。 |
| **摘要**（summary） | `README.md` 等面向第一次读的人的材料 | 给结论 + 指向属主。**与属主冲突时，一律以属主为准。** |
| **记录**（record） | `roadmap.md` / `feasibility.md` / `assessment-*.md` / `review-*.md` / `history/**` | 写的是**当时**的判断，保留原话是**故意的**。**不得当现状读**，也不要求与属主逐字一致。 |

> 因此本文档**不追求"全文只出现一次单进程"** —— 那会毁掉记录。
> 它保证的是：**改动只需要落在属主一处，读者永远知道哪一处算数。**

## 4. 归档规矩（`docs/history/`）

1. 只有**被后续版本明确取代**的文件才移进 `history/`；移入时必须在开头加一行
   `⚠️ 历史快照（已归档）…以 <当前文件> 为准`，并说明"文内对其它文档的引用均指 `docs/` 下的同名文件"。
2. 移入后必须把仓库里所有对它的引用改成 `docs/history/…`。
   一查即知：`grep -rn "assessment-" README.md docs app tools`（应只剩 `history/` 前缀的命中）。
   ⚠️ 一个**刻意存在的例外**见 [`versioning.md`](versioning.md) §4：历史迁移 `0015_*.sql` 里的旧文件名
   不参与改名（迁移有校验和，改一个字符就会让已部署的库报错）。
3. **不要**把 `roadmap.md` / `feasibility.md` 归档 —— 它们随版本**持续增补**，是主线材料，不是快照。

## 5. 新增文档前先问两句

1. **这条陈述的属主是谁？** 如果答案是"已有文档里已经写过"，那就去**改那里**，不要在别处再写一遍。
2. **这份文档属于哪一类（属主 / 摘要 / 记录）？** 决定它该写"现在是什么"还是"当时怎么想"。
